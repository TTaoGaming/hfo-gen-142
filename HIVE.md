# Gen142 Zerg Hive — Integrated Target

Purpose: integrate the surviving Gen142 pieces into one standards-native, COTS-owned swarm organism that a fresh carrier can enter through one gateway without Tao manually re-explaining or routing the system.

## Target loop

`GATEWAY -> UNCOMMITTED_CAPACITY -> WORKLOAD_SELECT -> CAPABILITY_ADMISSION -> JIT_MORPH -> SKILL_LOAD -> TOOL_USE -> DURABLE_ACTOR/BURROW -> PDSA -> EVIDENCE -> REDUCE -> CONSUMER_ACK -> RELEASE/REMORPH`

The Hive is the composition of this loop. It is not one giant agent and it is not permission to build a second orchestration stack.

## Hard ontology

`WORKLOAD != CAPACITY != CARRIER != ACTOR != PHENOTYPE != SKILL != TOOL != AUTHORITY != EVIDENCE`

- **Workload** = durable demand / unresolved edge.
- **Capacity** = available cognition/compute supply.
- **Carrier** = disposable model/chat/process episode.
- **Actor** = durable logical identity/state owner when one is actually admitted.
- **Phenotype** = late-bound work role such as Twinling, Roach, Reducer, Verifier.
- **Skill** = reusable procedure loaded only when relevant.
- **Tool** = MCP/provider-native/CLI/API resource interface.
- **Authority** = separately admitted effect ceiling; never implied by role/card/skill/tool reachability.
- **Evidence** = durable observations, claims, falsifiers, receipts, provenance and ConsumerAck.

## Native ownership

- Cloudflare Agent / Durable Object = durable actor identity + hot actor state.

- Fiber/schedule = recoverable actor-local/background work where appropriate.
- Cloudflare Queues = buffering/backpressure with at-least-once semantics; idempotency required.
- Service Bindings / Workers RPC = in-Cloudflare invocation.
- AI Gateway/provider APIs = model routing/credentials/policy where useful.
- A2A Agent Card = discovery/self-description of an actually served durable agent.
- Agent Skills = progressively disclosed reusable procedures.
- MCP/provider-native API/CLI = tool/resource seams.
- CloudEvents + W3C Trace Context + W3C PROV + UTC = evidence/event interoperability profile.
- GitHub = institutional evidence, admission, recovery and lineage.

## Hive representation rule

Do not create one A2A Agent Card per metaphor.

Most Zerg terms are **capacity archetypes, workload phenotypes, procedures, or platform-owned mechanisms**, not independently served agents. Only a durable live endpoint with truthful runtime facts earns an Agent Card.

Examples:
- Larva -> capacity archetype / gateway state, usually no Agent Card.
- Twinling -> formation + Skill contract, usually no Agent Card.
- Roach -> durable continuation/fan-in phenotype backed by a Burrow; card only if exposed as an actual served durable agent.
- Queen -> workload-to-capacity allocation policy; do not reify as an agent if Workflow/Agent/native policy owns the function.
- Hatchery -> launch/admission mechanism; prefer platform workflow/scheduler semantics.
- Burrow -> durable state slot/topology, not an agent identity by itself.

See `ZERG_CAPACITY_ARCHETYPES.md`.

## Hive acceptance — R0

A Hive claim is not earned by documents alone. R0 requires one vertical slice in which:

1. a zero-history carrier receives only the Gen142 Gateway pointer;
2. it recovers current durable state without Tao context ferry;
3. it selects existing demand rather than inventing work from spare capacity;
4. it JIT-morphs into one admitted phenotype;
5. it loads only the needed Skill(s);
6. it discovers/reaches tools through native interfaces and stays inside effect authority;
7. one durable actor/Burrow checkpoint survives carrier death/replacement;
8. the replacement carrier resumes the same unresolved edge rather than restarting research;
9. the work emits evidence in the Gen142 interoperability profile and is reduced into canonical Strife/Splendor/world-state/heritage state;
10. a distinct downstream consumer records a ConsumerAck or explicit rejection;
11. duplicate accepted effects = 0;
12. Lenovo and Tao are not routine runtime dependencies.

## Integration discipline

- Build no new scheduler, queue, actor runtime, tool bus, model router, provenance system, or evolution framework unless a demonstrated native gap survives falsification.
- Keep public Gen142 sanitized; private donor evidence is referenced through safe pointers/hashes rather than copied wholesale.
- Preserve UNKNOWN and minority falsifiers.
- `MODEL_AGREEMENT != INDEPENDENT_EVIDENCE`.
- `AGENT_CARD_CLAIM != CAPABILITY_ADMISSION != EFFECT_AUTHORITY`.
- `HEARTBEAT != USEFUL_WORK`.
- `CAPACITY != DEMAND`.
